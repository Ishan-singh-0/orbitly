# Tweak’d

A marketplace where artists customise everyday products (bags, mice, mugs, hoodies, prints) and anyone can order them. Artists get portfolio pages and can list their campus; buyers pick the product, colour, size and artwork.
**Zero runtime dependencies** — just Node 18+. Security details: [SECURITY.md](SECURITY.md).

```
node server.js          # http://localhost:5180
npm run check           # syntax-check every file
```

## How it works now

- **Customers order custom work.** They pick what they own (or "Something else"), choose an artist, add inspiration pictures and links in the Inspiration tab, and describe the job. The artist replies with a quote; work starts only after the customer accepts.
- **Artists showcase their creations.** No fixed-price listings in the interface. Their work appears on their page and in the gallery.
- **Admins approve artists.** Anyone can apply; a page is private until approved at `/admin` → Artist approvals.
- **Help assistant.** Rule-based and runs in the browser (not an AI model). It answers questions about the site and looks up artists and your own orders.
- **Motion.** The home page rotates through six products; scroll, hover and order animations are switched off for people who ask for reduced motion.

## Demo accounts

When you run it locally (not in production) the first start creates three labelled demo accounts, so you can see every side of the site without signing up. The login window shows them as one-click buttons.

| Role | Email | Password | What you see |
| --- | --- | --- | --- |
| Buyer | buyer@tweakd.demo | Buyer-Demo-2026 | Browse, customise, order, review |
| Artist | artist@tweakd.demo | Artist-Demo-2026 | Showcase and one custom request waiting for a quote |
| Admin | admin@tweakd.demo | Admin-Demo-2026 | The management console at `/admin` |

On a public showcase (`DEMO_SEED=1` in production) the three demo accounts are shared, so their login details can't be changed or deleted and the demo admin is read-only.

The artist's four artworks are generated by the server, not made by a person. Set `DEMO_SEED=0` to switch this off locally. It never runs in production unless you set `DEMO_SEED=1`; if you do, change those passwords first or delete the accounts.

## What's real

Nothing on the site is demo content. Everything comes from real activity:

| Feature | How it works |
| --- | --- |
| Accounts | Sign up / log in, scrypt hashing, HttpOnly session cookies, lockout after repeated failures |
| Email | Verification, password reset and "new message" emails (via Resend; dev outbox when no key) |
| Artist pages | `/@handle` — address, portfolio, campus, country, banner colour, portrait, bio, skills, website |
| Portfolio | Image uploads (JPG/PNG/WebP, resized in the browser, type checked by file signature, stored in `DATA_DIR/uploads`) |
| Products | 12 blank products (tote, backpack, laptop sleeve, mouse, desk mat, phone case, t-shirt, hoodie, mug, bottle, notebook, framed print) drawn as live SVG mockups |
| Customiser | Buyer picks colour, size, quantity and one of the artist's artworks and sees it on the product before sending the request |
| Campuses | Artists can list a college; buyers can filter by campus |
| Listings | Product, cover artwork, price, delivery time, description and "what's included" — live for everyone instantly |
| Messaging | Two-way conversations, service requests, unread counts — delivered in real time |
| Live stats & presence | Members / sellers / services / people online and the "Online now" dot, pushed over Server-Sent Events |
| Exchange rates | Fetched from ExchangeRate-API every 6 hours |
| Orders & reviews | A service request creates an order (requested → in progress → delivered → completed, plus decline/cancel/revision). Only buyers of completed orders can leave a 1–5 review, so ratings are real |
| Two-step login | Optional TOTP (any authenticator app) with a QR code, 10 one-time recovery codes, secret encrypted at rest |
| Bot protection | Self-hosted proof-of-work CAPTCHA (no third party) on sign-up, contact, password reset, and login after failures |
| Devices | See where you're signed in and sign out everywhere else |
| Admin console | `/admin` for admin accounts: members (ban, delete), listings, orders, payments (payout, refund), reports. Give an account admin rights with `node tools/make-admin.js you@example.com` (server stopped). In production an admin must have two-step verification on |
| Account control | Change name/password, email preferences, download your data, delete your account |
| Moderation | Report links, contact inbox, admin API + CLI to ban users and remove content |
| SEO | Per-page title/description/Open Graph, JSON-LD, `sitemap.xml`, `robots.txt`, `security.txt` |
| Fonts | Self-hosted (Inter, Instrument Serif — SIL OFL). No third-party requests |

### What it does **not** do (yet)
- **Automatic artist payouts.** Checkout is built (Stripe hosted Checkout, off until you add keys; see [PAYMENTS.md](PAYMENTS.md)) but payouts to artists are recorded by you with `tools/admin.js payout`; Stripe Connect is the next step.
- **Printing and shipping.** The artist makes and ships each product; Tweak’d does not fulfil orders.
- **Identity verification or vetting** of sellers.
- **Image uploads** — covers and portraits are generated illustrations.
- **Email change, admin web UI, restore tool.**

## Configuration

Environment variables — copy from `.env.example`:

| Variable | Purpose |
| --- | --- |
| `NODE_ENV=production` | Production mode (binds `0.0.0.0`, request logging, no dev email outbox) |
| `PORT` | Port (default 5180) |
| `SITE_URL` | Public URL, e.g. `https://tweakd.com`. **Required in production** — validates the Host header, builds canonical/sitemap/email links |
| `TRUST_PROXY=1`, `TRUST_PROXY_HOPS` | Behind a TLS-terminating proxy: trust `X-Forwarded-*` for real IPs and `Secure` cookies |
| `FORCE_HTTPS=1` | Redirect HTTP → HTTPS |
| `DATA_DIR` | Where `db.json`, `sessions.json`, `backups/` live. **Mount a persistent disk here** |
| `RESEND_API_KEY`, `MAIL_FROM` | Enables real email. Without a key, production sends no email |
| `ADMIN_TOKEN` | 32+ chars enables the admin API for `tools/admin.js`; empty = disabled |
| `COMPANY_NAME`, `CONTACT_EMAIL` | Shown on legal pages / footer / `security.txt` |
| `ALLOWED_HOSTS` | Extra permitted hostnames (e.g. `www.your-domain.com`) |
| `APP_SECRET` | Optional. Signs captcha/2FA tokens and encrypts 2FA secrets. If unset, one is generated in `DATA_DIR/secret.key` (back it up with the data) |
| `CAPTCHA=off`, `CAPTCHA_BITS` | Disable the proof-of-work check, or set its difficulty (default 18) |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | Both set = online payment on. Use test keys first. Webhook URL: `https://your-domain.com/api/stripe/webhook`, event `checkout.session.completed` and `charge.refunded` |
| `DEMO_SEED` | `0` turns the local demo accounts off; `1` forces them on (don't in production) |
| `PLATFORM_FEE_PERCENT` | Fee kept on each paid order (default 10), shown in `tools/admin.js payments` |

## Free showcase on Render

`render.yaml` is set up for Render's free plan: New → Blueprint → pick this repo. The free plan has no disk, so data resets whenever the service restarts or sleeps, and the three demo accounts are recreated each time. Good for showing the site to people; for real users use a paid plan with a disk and `DEMO_SEED=0` (Option B below).

## Deploying

You need **a persistent disk** (data is stored as JSON files) and **HTTPS**.

### Option A — Docker (any host)
```
docker build -t tweakd .
docker run -d --name tweakd -p 3000:3000 -v tweakd-data:/data \
  --read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges \
  -e SITE_URL=https://your-domain.com -e COMPANY_NAME="Your Company" -e FORCE_HTTPS=1 \
  -e RESEND_API_KEY=... -e MAIL_FROM="Tweak’d <noreply@your-domain.com>" -e ADMIN_TOKEN=... tweakd
```
Put it behind a reverse proxy that provides HTTPS (Caddy example below).

### Option B — Render / Railway / Fly.io
1. Create a **web service** from this repo (Node, start command `node server.js`).
2. Attach a **persistent disk/volume**; set `DATA_DIR` to its mount path.
3. Set the env vars above (`NODE_ENV=production`, `TRUST_PROXY=1`, `FORCE_HTTPS=1`, `SITE_URL`, …).
4. Point your domain at it. Health check path: `/healthz`.

### Option C — Your own server with Caddy (automatic HTTPS)
```
# Caddyfile
your-domain.com {
  encode gzip
  reverse_proxy 127.0.0.1:3000
}
```
Run with `NODE_ENV=production PORT=3000 TRUST_PROXY=1 SITE_URL=https://your-domain.com DATA_DIR=/var/lib/tweakd node server.js` under systemd/pm2.
With nginx, disable buffering for `/api/stream` (the server already sends `X-Accel-Buffering: no`).

## Launch checklist

- [ ] Set `SITE_URL`, `COMPANY_NAME`, `CONTACT_EMAIL`, `TRUST_PROXY`, `FORCE_HTTPS`, `DATA_DIR` (persistent!)
- [ ] Create a Resend account, verify your domain, set `RESEND_API_KEY` + `MAIL_FROM` (SPF/DKIM per Resend's instructions)
- [ ] Set `ADMIN_TOKEN` (32+ random bytes) so you can moderate
- [ ] **Have a lawyer review** the Privacy Policy and Terms (`public/pages.js`) for your jurisdiction — they're a sensible general template, not legal advice
- [ ] Add a 1200×630 share image at `public/og.jpg` (share tags appear automatically once it exists)
- [ ] Go through the hosting-side list in [SECURITY.md](SECURITY.md) (firewall, patching, off-box backups, CDN/WAF)
- [ ] Submit `https://your-domain.com/sitemap.xml` to Google Search Console
- [ ] Set an uptime monitor on `/healthz`
- [ ] Plan for growth: JSON-file storage is fine early on; move to SQLite/Postgres before thousands of active users or more than one instance

## Operations

```
# moderation (server must have ADMIN_TOKEN set)
ADMIN_TOKEN=... ADMIN_URL=https://your-domain.com node tools/admin.js overview
                                                                       payments | payout <orderId> | refund <orderId>
                                                                       reports
                                                                       ban <userId> | unban <userId>
                                                                       delete-user <userId> | delete-gig <id> | dismiss <reportId>

# emergency password reset (stop the server first)
node tools/reset-password.js user@example.com "new-long-password"
```
- **Backups:** automatic daily copy to `DATA_DIR/backups` (last 14). Also copy `DATA_DIR` off the machine.
- **Logs:** security events (sign-ups, failed/locked logins, resets, admin actions) go to stdout as JSON lines.
- **Dev email:** outside production, emails are written to `DATA_DIR/outbox/` so you can click the links locally.
